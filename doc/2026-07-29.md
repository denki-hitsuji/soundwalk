# 2026-07-29: ライブ情報公開APIの仕様書を外部公開用ページとして追加

## 経緯

- Hugo側のプロジェクトから今回のAPI（`GET /api/public/bands/{slug}/lives`）を実際に呼び出して実装したいとの相談。
- ユーザーの認識（1. 内部事情を知らない人向けの仕様書作成、2. 公開に適したURL設定が必要）を確認し、認識は正しいと回答。
- ホスト先について確認したところ、「このNext.jsアプリ内に公開ページを追加」を選択。

## 実施内容

- [app/docs/api/live-events/page.tsx](../app/docs/api/live-events/page.tsx) を新規作成。`/docs/api/live-events` で閲覧可能。
  - [docs/api/hugo-live-events.md](../docs/api/hugo-live-events.md)（内部向け設計・決定ログ）とは別に、内部のファイルパス・意思決定の経緯・DBスキーマ事情などを一切含まない、外部の実装者（人・LLM問わず）向けのAPIリファレンスとして書き起こした。
  - 内容: エンドポイント・パスパラメータ・レスポンス/エラースキーマ・キャッシュ/レート制限・curlでの呼び出し例。
  - `app/(public)/layout.tsx`（ログイン導線付きの狭い認証系レイアウト）や `AppShell`（要ログイン前提のナビ）は使わず、`/bands/[slug]` と同様に単独ページとして実装（完全に認証不要な公開ドキュメントのため）。
- `next build` でルートが `○ /docs/api/live-events`（静的プリレンダリング）として生成されることを確認。
- `npm run dev` を一時起動し、`curl`でHTMLが200で返り、タイトル・エンドポイント表記・エラーコード等が正しくレンダリングされていることを確認（確認後サーバーは停止済み）。
